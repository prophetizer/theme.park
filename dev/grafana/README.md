# Local Grafana theme development

This setup supports the Grafana 13 base stylesheet, which replaces the old
`grafana` theme. That theme targeted class names generated by older Grafana
builds and was marked deprecated, so `themes.py` produced no per-theme files
for it and every Grafana theme link returned 404.

## Start and compare

Run from this checkout's root:

```sh
docker compose -f dev/grafana/compose.yaml up -d
```

| Address | Purpose |
| --- | --- |
| http://localhost:18090 | Native Grafana without theme.park injection. |
| http://localhost:18091 | Same app through nginx with theme.park CSS. |
| http://localhost:18870 | Live CSS and resources from this checkout. |

Anonymous access is on with the Admin role, so no login is needed. The
`admin` / `admin` account also exists for the login page. The home dashboard
is the provisioned **theme.park sample** (`/d/themepark-sample`), backed by
Grafana's built-in TestData source. It has one panel of each kind the sheet
touches: time series, stat, gauge, bar gauge, text (markdown with a link and
inline code) and a table.

Edit `css/base/grafana/grafana-base.css` and refresh port 18091. To change
the injected option or Grafana's own mode:

```sh
TP_THEME=aquamarine docker compose -f dev/grafana/compose.yaml up -d proxy
TP_THEME=catppuccin-latte TP_THEME_FOLDER=community-theme-options docker compose -f dev/grafana/compose.yaml up -d proxy
```

For a light option, switch Grafana itself to light mode with `?theme=light`
on any URL (for example `http://localhost:18091/d/themepark-sample?theme=light`).
The anonymous user ignores `default_theme`, so the compose file can't set it.

`GRAFANA_TAG` selects another release (default 13.2.3).

## How the stylesheet hooks in

Grafana 13 styles everything with Emotion classes (`css-xxxx`) that change
between builds, and exposes no CSS variables. The base sheet only uses hooks
Grafana keeps stable for its tests and accessibility: `data-testid` values,
ARIA roles, element names, `main#pageContent`, `body.app-grafana`, and
react-data-grid's `rdg-*` classes for tables. Every rule is scoped under
`body.app-grafana:not(.login-page)`. That out-ranks Emotion's single-class
rules without `!important`.

The login page is deliberately left alone: its box stays dark over Grafana's
own backdrop, and themed text there was unreadable.

## Known limits

- Chart contents are not themed. Axes, grid lines and series in time series,
  gauges and bar gauges are drawn on a canvas or coloured by thresholds, and
  those colours carry meaning. On bright gradient options such as hotline,
  some of Grafana's own value colours read poorly against the panel.
- Match Grafana's own light/dark mode to the option's mode (Profile >
  Preferences, or `?theme=light`). With a light option on dark-mode Grafana,
  canvas axis text, gauge values and bar-gauge tracks keep their dark-mode
  colours on a light panel. The main menu is themed so it stays readable.
- Verified on 13.1.1 and 13.2.3 in Chromium at 1440x900, with every option
  in `css/theme-options/`, plus catppuccin-latte in light mode. Not verified:
  Firefox, Safari, phone widths, alerting and explore pages in depth, and
  Grafana 12 or older.
